# P008 倍行镜 JoinWitness — 用户使用与操作指南 (USER_GUIDE)

> **版本**：1.0.0 (SPEC 1.0.0)  
> **定位**：面向中小团队与数据分析师的基表度量倍增分解、金额归因与最小反例分析工具  
> **运行环境**：纯本地浏览器运行（零外部网络请求、零后端数据库、零用户数据持久化）

---

## 1. 工具背景与解决的问题

在基于 SQL 的数据报表与 BI 指标汇总中，当在基础维度表（如订单表 A）上对多明细表（如发货明细 B、支付明细 C）进行 `LEFT JOIN` 时，由于一对多（1:N）或多对多（N:M）关联，基础表记录会被静默复制多倍。如果直接在连接后的宽表上执行 `SUM(A.amount)`，就会产生灾难性的“指标倍增翻倍”（Fanout Inflation）。

例如，在经典的订单与发货/支付多表汇总场景中：
- 真实基表订单总额为 **¥86.00**（3 笔订单）；
- 经两跳或双支路 LEFT JOIN 后，总行数膨胀至 **8 行**，简单 `SUM` 结果变成了 **¥284.00**，虚增了 **+¥198.00**；
- 更有甚者，当存在正负金额抵消时，表面上的总额差额可能为 **0.00**，但内部依然存在严重的虚构行倍增！

**倍行镜 JoinWitness** 提供了一套纯前端、零依赖后端、精确到分（基于 `BigInt`）的可视化诊断工作流：
1. **倍增因子分解（Factorized Decomposition）**：逐行分析基表记录在拓扑中的乘积/相加复制因子；
2. **金额归因（Amount Attribution）**：精确计算安全基表金额（Safe）、虚增金额（Naive）与虚增偏差（$\Delta$）；
3. **最小结构见证集（Minimal Witness）**：算法自动提取能够解释该倍增现象的最小行数子集（如 3 行或 4 行），无需人工在大宽表中翻找；
4. **离线安全（Strict Offline Privacy）**：所有计算在 Web Worker 中完成，绝不向任何外部服务器上传数据。

## 2. 快速启动与页面布局

### 2.1 访问方式
JoinWitness 为纯静态单页应用（SPA）。在部署或本地构建后，通过任意现代浏览器（Chrome、Chromium、Firefox、Edge 等）打开 `http://127.0.0.1:4173/` 或本地静态服务器即可使用。

### 2.2 核心视口与布局（1440×900 优化）
在 1440×900 标准桌面上，首屏无需滚动即可完整浏览核心诊断指标：
- **顶部导航栏 (Navbar)**：
  - 应用标题与副标题；
  - 合成数据来源安全标识（`合成数据 · 不代表真实企业`）；
  - 黄金预设下拉框（JW-A 至 JW-F）；
  - 数据操作按钮（打开 CSV 导入向导、导入 JSON、导出 JSON、重置状态）。
- **指标摘要栏 (Metric Summary Cards)**：
  - **总行数对比**：基表行数 $\to$ JOIN 展开后总行数（如 `3 → 8 行 (+5 行)`）；
  - **金额指标对比**：安全总额（Safe SUM）与天真总额（Naive SUM）（如 `¥86.00 → ¥284.00`）；
  - **虚增偏差**：净偏差金额与虚增百分比（如 `+¥198.00 (+230.23%)`；若基表为 0 则显示 `N/A`）；
  - **拓扑信息**：当前连接模式（星型双支路 Star 或多跳链式 Chain）。
- **核心可视化与拓扑图 (GraphView)**：
  - 左侧展示 2 表或 3 表的节点拓扑与实际 JOIN 键；
  - 动态展示每条基表记录在经过外连接时的倍增倍数；
  - 支持键盘聚焦与点击单行高亮。
- **证据与分析面板 (DetailTabs)**：
  - **拓扑与倍增条形图 (Topological Breakdown)**：逐行柱状图展示复制倍数与虚增金额；
  - **连接预览 (JOIN Preview)**：交互式数据表格，严格限制最多 200 行防卡死预览；
  - **最小见证集 (Minimal Witness)**：算法提取的最小反例子集，支持一键复制 JSON；
  - **安全粒度与业务说明 (Granularity Explanation)**：解释为什么不能盲目使用 `SUM(DISTINCT)`，给出业务建模建议。

## 3. 六大冻结黄金预设详解

系统内置 6 个严格锁定的合成黄金预设，均标注“合成”：

| 预设编号 | 预设名称 | 拓扑类型 | 关键指标 | 典型学习意义 |
|---|---|---|---|---|
| **JW-A** | 双支路暴增（合成） | Star 双支路 | 3→8 行；¥86.00→¥284.00 (+¥198.00)；见证 3 行 | 经典 1:N 发货与 1:N 支付交叉笛卡尔倍增 |
| **JW-B** | 链式多对多展开（合成） | Chain 链式 | 2→6 行；¥37.00→¥157.00 (+¥120.00)；见证 3 行 | 多跳链式连接（Orders $\to$ Payments $\to$ Receipts）倍增 |
| **JW-C** | 负数金额完全抵消（合成） | Single Join | 2→4 行；¥0.00→¥0.00 (+¥0.00)；见证 3 行 | 即使总额差为 0，依然存在两笔翻倍的非平凡见证 |
| **JW-D** | 孤立未连接与 SQL NULL（合成） | Single Join | 2→2 行；¥19.00→¥19.00 (+¥0.00)；见证 NONE | 严格遵循 SQL 规范：NULL 键互不连接，LEFT 保留未匹配行 |
| **JW-E** | 单表左连接无倍行（合成） | Single Join | 2→2 行；¥24.00→¥24.00 (+¥0.00)；见证 NONE | 澄清误区：两笔同为 12.00 的真实订单不能被 `SUM(DISTINCT)` 误去重 |
| **JW-F** | 链式最小见证集示例（合成） | Chain 链式 | 1→2 行；¥10.00→¥20.00 (+¥10.00)；见证 4 行 | 链式连接下最小反例包含 A、B 与两条 C，结构下界为 4 行 |

## 4. 数据导入与向导操作

### 4.1 CSV 导入向导 (CSV Wizard)
点击导航栏的 **「CSV 导入向导」** 按钮：
1. **选择表模式**：支持 2 表模式（A $\leftarrow$ B）或 3 表模式（Star：B $\leftarrow$ A $\rightarrow$ C；Chain：A $\rightarrow$ B $\rightarrow$ C）；
2. **录入/粘贴 CSV 文本**：
   - 支持包含双引号、转义字符、换行符以及 UTF-8 BOM 的 RFC4180 合规 CSV；
   - 包含主键列、外键关联列、金额列；
3. **映射列角色**：
   - 基础表 A：选择主键列（必须唯一）、金额列；
   - 关联表 B / C：选择关联键列；
4. **实时校验拦截**：
   - 若基表主键有重复、金额包含非数字非法字符、或键列缺失，向导将以明确文字提示阻断并指引修复；
5. **完成导入并运行**：点击「确认导入」，工作线程立即执行分析并渲染结果。

### 4.2 JSON 场景导入与导出
- **导出 (Export)**：点击 **「导出 JSON」** 按钮，系统生成包含 `schema`、`specVersion: "1.0.0"`、来源标记（`preset` 或 `user_import`）、时间戳以及全部表数据的规范化 JSON。
- **导入 (Import)**：点击 **「导入 JSON」** 按钮，选择符合 `Scenario v1` 契约的文件，系统自动校验并载入。

## 5. 核心算法与指标计算口径

1. **倍增因子（Multiplication Factor $F(a)$）**：
   - 对于基表记录 $a \in A$：
   - 在 **Star** 拓扑中：$F(a) = \max(1, count_B(k_B)) \times \max(1, count_C(k_C))$；
   - 在 **Chain** 拓扑中：$F(a) = \sum_{b \in Match(a)} \max(1, count_C(b.k_C))$（若无匹配则为 1）；
2. **金额精度保证（BigInt Cent-Level Attribution）**：
   - 规避 JavaScript 浮点数丢失精度的缺陷，全部金额解析为整数“分”（Cents），以 `BigInt` 累加；
   - $S_{\text{safe}} = \sum_{a \in A} \text{amount}(a)$；
   - $S_{\text{naive}} = \sum_{a \in A} F(a) \times \text{amount}(a)$；
   - $\Delta = S_{\text{naive}} - S_{\text{safe}}$；
3. **最小结构见证集（Minimal Witness Set）**：
   - 寻找导致倍增的最小行数子集。如果全场景无倍增（如 JW-D、JW-E），见证显式显示 `NONE`；
   - 支持展开查看每行在见证集中的 ID 与角色，并可一键复制见证 JSON。
4. **200 行预览保护**：
   - 为了防止超大笛卡尔积导致浏览器 DOM 挂起，连接预览表格强制设置 200 行上限，明确标注 `已截断（仅显示前 200 行，总计 N 行）`，而总指标和因子图仍严格基于全量分解式计算。

## 6. 无障碍与环境适应

- **键盘导航与焦点**：页面所有交互按钮、下拉框、表格行与标签页均支持 `Tab` 键导航与明显的焦点轮廓，符合 WCAG 2.2 规范；
- **减少动态效果**：系统检测系统的 `prefers-reduced-motion` 设置，在开启减少动画时自动关闭所有平滑动效与条形过渡，同时完整保留所有文字与指标信息；
- **纯本地离线运行**：系统无需外网环境，阻断所有第三方跨域请求，断网状态下全部功能（预设、导入、导出、Worker 计算）完全可用。
